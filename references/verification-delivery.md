# 验收与交付

## 一、为什么必须看像素

曾经有一次：日志显示 8/8 段全部完成、refine 无报错、文件体积从 3.5 MB 涨到 6 MB，于是判定「成功」。实际成片每一帧都是同一个人物横向三重影 —— refine 的 tiling 把画面切成三块各自渲染后拼错。

**规则：日志只能证明流程跑通，证明不了画面正确。每次出片必须抽帧看，没有例外。**

## 二、必查的帧位

对 413 帧的成片：

| 帧号 | 时间 | 查什么 |
|---|---|---|
| 0 | 0.00s | 起始造型、构图 |
| 100 | 4.17s | 中段造型稳定性 |
| 200 | 8.33s | 快速运镜段是否叠影 |
| 300 | 12.50s | 后段造型漂移 |
| 412 | 17.17s | 结尾景别是否被推成特写 |

段缝另查：每个边界取 `边界-1` 与 `边界` 两帧（例：51/102/153/204/255/306/357），比对人物位置与大小是否连续。

## 三、检查清单

**画面完整性**
- 无人物横向重复、三重影、半透明叠影、马赛克色块
- 无第三个人、镜面人、虚影
- 原片背景（看台、灯光、地面、文字）保留

**造型一致性**
- 女性：脸、发型（发髻/发饰）、服装配色与款式、鞋
- 男性：脸、发型、长袍领型/袖型/长度/内衬/刺绣/鞋
- 两人不串脸、不串服装

**运动与构图**
- 构图、景别、机位、镜头运动与源片逐帧一致
- 人物全程全身在画面内，没有被推成半身/特写
- 结尾最后 2 秒景别与源片结尾相同
- 动作（招式、走位、手势、转身、节奏）与源片一致

**技术规格**
- 分辨率 / 帧率 / 总帧数与规划一致
- 无音轨（`ffprobe` 只有 video 流）
- 拼接无重复帧、无跳帧

## 四、用视觉模型辅助验收

抽帧后用 `ViewImage` 逐帧提问，问题要写具体，例如：

> 画面是否干净：有无半透明叠影、三重影、马赛克？描述两人服装发型、姿态、景别与背景。

对比类问题（判断二采是否更优）：

> A 图与 B 图相比，布料纹理与发丝分离度哪个更清楚？面部是否被过度平滑？

## 五、交付

1. 成片 scp 回本地：`<LOCAL_DELIVER_DIR>/`
2. 命名带规格：`<主体>_swap_<宽>x<高>.mp4`
3. 汇报时给全规格：分辨率、帧率、帧数、时长、体积、音轨、分段方式、总耗时、已知瑕疵
4. 默认只给路径与局域网链接；用户明确要「文件本体」时才用 `present_files` 发到会话
5. 局域网页面（如启用）：`http://<MAC_LAN_IP>:8766`，出片后自动同步，页面数据源前缀须同步改成当前任务前缀

## 六、汇报模板

```
成片：<文件名>（<路径>）
规格：<W>×<H> / <fps>fps / <N> 帧 / <秒>s / <MB> MB / <有|无>音轨
参数：<段长组合>，融合 <N> 帧，二采 <开/关>，种子 <seed>
耗时：<总时长>
抽查：0 / 25% / 50% / 75% / 末帧，段缝 <列表>，结论 <干净 | 具体瑕疵位置>
已知问题：<无 | 描述 + 建议下一步>
```
